# ReadAlong UI 优化方案

## 目标

让用户更快进入英语阅读与跟读流程，同时减少偏好设置侧栏的滚动和视觉负担。

## 现状

- 设置侧栏把朗读、文字显示、儿童模式、外观、转写与版本信息放在同一纵向列表中。
- “配置”面板展开后继续容纳多个折叠组，侧栏内容会变成长列表。
- 阅读主区使用大卡片和渐变背景。空白态的导入动作与已进入阅读后的正文层级相近。
- 音频播放区同时显示文件名、进度、识别状态、播放控制和朗读来源，控件密度较高。

## 建议方案

### 1. 设置侧栏

- 移除包住所有偏好项的“配置”折叠层，让“文字显示”“儿童模式”“外观与主题”“本地高精度转写”“关于”成为同级项目。
- 保留“TTS 发音”作为独立的常用分组。
- 默认只展开 TTS 发音。一次只允许一个设置面板展开，避免多个面板把侧栏推成长列表。
- 缩短说明文字。把详细帮助放进辅助说明或单独帮助入口。

### 2. 阅读空白态

- 将“粘贴文本”和“选择文件”设为两个清晰的主入口。
- 保留轻量的书本插图和一句简短提示。
- 首次打开时把焦点放到可输入区域，导入后切换为阅读布局。

### 3. 阅读状态

- 正文成为主视觉，缩小顶部介绍卡片。
- 把词数、阅读进度和翻译状态收进紧凑状态栏。
- 继续使用紫色主题和黑色主题，但让两者共用相同的控件层级、间距和强调色规则。

### 4. 音频控制

- 固定播放区高度和控件位置，识别状态更新时不改变布局。
- 文件名和时间作为一行，进度条作为一行，播放与精听作为主要操作。
- 将朗读来源和倍速作为次级控制，窄窗口下允许折叠到更多菜单。

## 实施顺序

1. 先拆掉外层“配置”折叠层，并将设置项改为同级面板。这能直接减少展开深度。
2. 调整空白态的粘贴和导入入口。
3. 整理音频控制区的层级和窄窗口布局。
4. 用 macOS 与 iPad 窗口尺寸检查间距、截断和键盘焦点。

## 验收标准

- 设置项最多一层展开，常用朗读设置不需要先展开“配置”。
- 空白态的粘贴与导入入口在初次打开时清楚可见。
- 音频识别状态变化不会让播放按钮和进度条跳动。
- 窄窗口下标签不截断，主要操作仍可触达。
